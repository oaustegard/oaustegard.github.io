Operator & parameter reference

Bluesky's search takes free text in q plus structured filter params alongside it. The classic operators still work inside q and are merged with the params, so a URL can carry either or both.

Inside q

SyntaxEffect
"exact phrase"Phrase match
-wordExclude a word
(a OR b)Alternation group
#tagHashtag
from:handle, from:meAuthor
mentions:handle, to:handleMentions an account
domain:example.comLinks to a domain
url:https://…Links to a URL
lang:enPost language (ISO 639-1)
since:2026-01-01 / until:Date range

Sibling params on /search

ParamValue
author, mentions, domain, url, tagSpace-separated list, OR-matched
excludeAuthor, excludeMentions, excludeDomain, excludeUrl, excludeTagSame, negated
langISO 639-1 code
since, untilYYYY-MM-DD
repliesnone or only
media, video, followingtrue
fromme

The exclude, replies, media, video and following filters have no operator equivalent — they exist only as params. Older Bluesky clients that only read q will ignore them.
